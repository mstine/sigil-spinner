<objective>
Complete the phase's two consumer surfaces: the JSON working that narrates the whole derivation
(OUT-01, D-14) and the full CLI flag surface (INT-02, D-09 through D-12), then document the
determinism contract that makes the tool safe to embed in a build pipeline.

a teaching page can read the derivation back out and check it by hand. The CLI surface is what makes
the tool composable from a build script, which is its primary consumer.

`--json`, and `--output`, library-side planet validation with stable error codes, a determinism
snapshot suite, and a README that states the contract.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv / stdin → library | Untrusted user text and an untrusted `--output` path cross here |
| library → JSON working → consuming page | The working carries the raw statement into whatever renders it |
| CLI stdout → consuming build pipeline | The pipeline treats the stream as a trusted artifact |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02 | Tampering | `bin/sigil-spinner.js` stdout stream | high | mitigate | stdout carries only the selected artifact; every diagnostic goes to stderr; nothing is written to stdout before the artifact is fully known; `--output` leaves stdout empty; subprocess tests assert empty stdout on every error path |
| T-01-04 | Information Disclosure | `working.statement` rendered by a downstream consumer | medium | transfer | Documented in the JSDoc and the README Data Handling section as untrusted input the consumer must HTML-escape; the library returns data, not markup, and does not escape on the consumer's behalf |
| T-01-09 | Tampering | `--output <file>` path | low | accept | The path comes from the invoking user's own shell and is written with the invoking user's own privileges; no privilege boundary is crossed, so path restriction would only constrain the user against themselves |
| T-01-10 | Denial of Service | stdin read via file descriptor 0 on a dash positional | low | accept | A synchronous read of an unbounded pipe can block or exhaust memory, but the input is supplied by the invoking user in their own process; documented rather than bounded |
</threat_model>
