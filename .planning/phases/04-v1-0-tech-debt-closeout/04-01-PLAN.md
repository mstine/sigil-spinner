fed back into `generateSigil`, contradicting `src/render/json.js`'s own doc

for a TypeScript consumer, an inverted regression test, and end-to-end round-trip

## Plan-level decisions

No `CONTEXT.md` exists for this phase — `/gsd-discuss-phase` was not run, so there
are no locked user decisions. The choices below were open; each takes the
RESEARCH.md recommendation and is recorded here so it is visible and reviewable
rather than implicit. Decision IDs continue from D-48, the highest in the project.

**D-49 · Fix WR-01 by widening the type-keyed absent-check, not by special-casing `idPrefix`.**
`resolveOptions` already iterates a declarative `KNOWN_OPTIONS` type table and
reads defaults from a parallel `ABSENT_DEFAULT_BY_TYPE` table. The fix extends
that same absent-check to also treat a value strictly equal to the option's own
type-keyed absent default as absent. This is type-scoped by construction:
`ABSENT_DEFAULT_BY_TYPE.boolean` is `false`, so `{ glyph: null }` still throws
exactly as before. A bespoke `idPrefix`-specific branch, or a loose `value == null`
check, are both rejected — the first duplicates a table that already exists, the
second silently makes `{ glyph: null }` valid and breaks the boolean guard.

Two rejected alternatives, for the record: dropping the `idPrefix` key at
serialize time instead of emitting `null` reopens D-48 (which deliberately chose
an invariant key set over `JSON.stringify` dropping `undefined`); and a separate
`reproduceFromWorking()` helper leaves the exact call `json.js` documents still
broken while adding a second entry point.

**D-49a · The `null idPrefix` test at `test/cli/cli.test.js:461-472` is inverted deliberately.**
That test currently asserts the broken behavior ("throws E_INVALID_OPTION for a
null idPrefix") as if it were correct. Under D-49 that assertion is wrong and
must flip to assert success. This is recorded here so a future reader or reviewer
scanning the diff sees a test whose meaning changed **on purpose**, not one that
was quietly loosened to make a fix pass. The sibling test at
`test/cli/cli.test.js:389-400` (`{ glyph: null }` throws) is the regression guard
proving the scoping and must survive completely unmodified.

**D-50 · `GenerateOptions.idPrefix` widens to `string | null`; the round-trip is NOT silenced with a cast.**
`working.render.idPrefix` is typed `string | null`. `GenerateOptions.idPrefix` is
JSDoc-typed `{string}`, i.e. `string | undefined`. Verified during planning by
running `tsc --checkJs` against a probe: the round-trip call fails with
`TS2345: Argument of type '{ curve: boolean; glyph: boolean; idPrefix: string | null; title: boolean; }'
is not assignable to parameter of type 'GenerateOptions'`. The runtime fix alone
therefore leaves the contract broken for exactly this project's stated primary
consumer — Claude Code invoking the library programmatically with types. The
typedef widens so the round-trip is legal at the type level too. Annotating the
test call site to suppress the error is explicitly rejected: it would hide the
defect rather than fix it.

**Reversibility:** see the `<reversibility>` block on Task 1. Nothing in this plan
is one-way, so no `checkpoint:decision` is inserted.
