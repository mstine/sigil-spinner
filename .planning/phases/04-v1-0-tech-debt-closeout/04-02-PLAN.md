## Plan-level decisions

**D-51 · Extra positionals are a hard usage error (exit 2), not a warning.**
The alternative — print a warning to stderr and render the first statement
anyway — was rejected. This CLI already exits 2 with a diagnostic for an
unrecognized flag and for a flag missing its value; accepting a malformed
invocation and proceeding would make the argv posture inconsistent, and a
pipeline that silently rendered the wrong sigil is worse than one that stopped.
The diagnostic reuses the file's existing `E_CLI_USAGE` code and
`CLI_USAGE_EXIT_CODE`, so a calling script can still branch on exit status alone.

**D-52 · The README's working fields move from an inline prose list to a field-reference table.**
The list has grown from the 11 fields the prose names to the 15 the typedef
actually declares, and prose lists do not scale past roughly a dozen entries. The
table's type and description text is transcribed from `src/render/json.js`'s
`SigilWorking` JSDoc typedef, which RESEARCH.md's ownership table names as
authoritative — the README tracks the typedef rather than re-authoring prose that
can drift again.

**D-53 · The CLI-local diagnostic codes get documented alongside the library codes.**
`E_CLI_USAGE` and `E_CLI_STDIN` appear zero times in the README today (verified
during planning), yet the "Errors and Exit Codes" section presents itself as the
complete reference and a user hitting the new extra-positional diagnostic will
look there first. They are documented in a clearly separated block that states
they are CLI-local and never thrown as `SigilError`, so the library/CLI boundary
stays legible.

**Reversibility:** Task 1 is rated `costly` (see its `<reversibility>` block);
Task 2 is documentation and therefore reversible. Nothing here is one-way, so no
`checkpoint:decision` is inserted.
