Declare three module-level constants before the `describe`, all data rather than procedure
(D-72). `ENTRY_POINTS` is an array of objects, each with a `subpath` and a `namedExports`
array; seed it with one row for `'.'` whose `namedExports` are exactly the seven names

**Rung 1 — the manifest.** Run `npm pack --dry-run --json` with `cwd` set to the repo root.
Parse the JSON defensively: on this repo's npm (11.4.2, confirmed) the output is an **array**
whose first element carries `name`, `version`, `filename`, and `files` as an array of objects
with a `path` key — but npm 12 changed this to an object keyed by package name, so normalize
both shapes to a flat array of path strings before asserting rather than indexing blindly.
Assert every entry of `EXPECTED_TARBALL_FILES` is present, and assert every path in the
manifest satisfies `ALLOWED_TARBALL_ROOTS`. The second assertion is the one that catches a
widened `files` shipping planning documents or scratch output; make its failure message print
the offending paths.

**Rung 2 — the real install.** Allocate the scratch directory with
`mkdtempSync(path.join(os.tmpdir(), 'sigil-spinner-pack-'))` — `mkdtemp` guarantees a unique
directory per call, which is what makes two concurrent runs non-interfering. Pack for real
with `npm pack --pack-destination <scratchDir>`, run from the repo root, so the tarball lands
in the scratch tree and never in the repository working tree; read the produced filename from
the command's own JSON output rather than reconstructing it from name and version. Create an
empty project subdirectory inside the scratch tree, write a minimal `package.json` into it
(a name and a private flag are enough) so `npm install` behaves predictably, then run
`npm install <absolute tarball path> --no-audit --no-fund --ignore-scripts` with `cwd` set to
that project directory.

Then three assertions against the **installed** copy, never the dev tree:

1. *Zero transitive dependencies.* Read the project's `node_modules` directory. After
   filtering out `.bin` and any dot-prefixed entry, the only remaining top-level entry is the
   scope directory `@falkensmage`, containing exactly `sigil-spinner`. Assert that, so a
   dependency creeping in fails here rather than in a consumer's install.
2. *`exports` resolution from outside.* For each row of `ENTRY_POINTS`, write a `.mjs` probe
   file into the project directory that imports the row's `namedExports` from the package
   name joined with the row's `subpath`, asserts each imported binding is defined, calls
   `generateSigil(STATEMENT, PLANET)` for the `'.'` row, and writes the resulting `svg` to
   stdout. Execute it with `execFileSync(process.execPath, [probePath], { cwd: projectDir, encoding: 'utf-8' })`.
   The `.mjs` extension is load-bearing and deliberate — Node treats `.mjs` as ESM
   unconditionally regardless of any `"type"` field, so the probe exercises the same
   resolution algorithm a real consumer's `import` walks, with one fewer moving part. A
   failure here surfaces as `ERR_PACKAGE_PATH_NOT_EXPORTED` or `ERR_MODULE_NOT_FOUND`, which
   is exactly the fault class this test exists to catch.
3. *The installed bin, byte-identical.* Run `execFileSync(process.execPath, [path.join(projectDir, 'node_modules', '.bin', 'sigil-spinner'), STATEMENT, '--planet', PLANET], { encoding: 'utf-8' })`.
   Resolve the bin through the `node_modules/.bin` shim path rather than shelling out to
   `npx`, so the assertion does not depend on network state or on npx's resolution order.
   Compare its stdout against the output of the **dev tree's** CLI at
   `path.join(REPO_ROOT, 'bin', 'sigil-spinner.js')` invoked with the same arguments, and
   assert byte equality. Comparing installed-against-dev rather than against a committed
   snapshot is what makes this catch a real `files`/`exports` fault instead of merely proving
   the tarball unpacks — a snapshot would still pass if the installed copy were resolving to
   a stale or partial tree, as long as the bytes happened to match.

**Cleanup (D-73).** No test in this repo performs teardown, so this is new machinery; build
it fresh. Wrap the rung-2 body in a `try`/`catch`. On success, `rmSync(scratchDir, { recursive: true, force: true })`.
On failure, do **not** remove it — rethrow an error whose message includes the original
message and the absolute scratch path, so an `exports` resolution failure is diagnosable after
the fact. A reused or auto-deleted tree would let a stale `node_modules` mask exactly the
misconfiguration this test exists to catch.

Follow the repo convention that the suite fails loudly rather than skipping: if `npm` is not
on `PATH`, or the pack produces no tarball, throw with a message saying so. Do not add a
conditional skip.

`node:` imports are fine in this file — it is a test, and the repo confines `node:` imports
to `bin/` and `test/`. Nothing in this phase touches `src/`.

**Trigger (D-76).** `workflow_dispatch` only. Do not add `push`, `pull_request`, `schedule`,

**Inputs.** Exactly two, both `type: choice` with a closed option list and a declared

reach a shell command in a job holding a publish credential.

`id-token` grant is what lets npm mint the Sigstore-backed provenance attestation from the
run's OIDC claims; the repository is public (confirmed), which provenance also requires. Add
nothing beyond those two — no `packages`, no `contents: write`.

**Job.** One job on `ubuntu-latest`, with a `concurrency` group keyed to the workflow so two
dispatches cannot race the registry, and `cancel-in-progress` left false (cancelling a publish
mid-flight is worse than queueing it).

Pin both actions to a **full 40-character commit SHA**, not a moving tag, with the human-readable
version in a trailing comment. This is the one workflow that holds registry-write credentials,

`registry-url` input is what makes `setup-node` write the runner's `.npmrc` so `NODE_AUTH_TOKEN`
is picked up. Do not hand-write an `.npmrc` step — that is the documented mechanism, and a
hand-rolled version risks the token reaching the logs if any step ever dumps file contents.
