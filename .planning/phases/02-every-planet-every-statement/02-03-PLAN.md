## Locked geometry specification

This is the contract the diagnosis returned. Tasks 2 and 3 implement exactly this.

**Anchor.** Let `p` be the repeated cell's center, `points[repeat.atPoint]`. Every loop for that event starts at `p`, passes through the antipode `q`, and returns to `p`. The emitted path data is `M p A r,r 0 1,1 q A r,r 0 1,1 p` — two arc commands, identical radii, rotation 0, large-arc flag 1, sweep flag 1 on both, so the two semicircles run the same way and close into one circle. The circle's implied center is `p + r*u`; `p` itself lies on the circle, which is what makes the marker connected to the traced line.

**Bulge direction `u`.** A unit vector perpendicular to the run's REAL travel, resolved in this order:
1. The segment entering the run's FIRST point: the segment whose `to` equals `repeat.atPoint - repeat.count`. Travel is that point minus its `from` point.
2. Otherwise the segment leaving the run's last point: the segment whose `from` equals `repeat.atPoint`. Travel is its `to` point minus `p`.
3. Otherwise the fixed deterministic vector `{ x: 1, y: 0 }`, used directly as `u` (no perpendicular taken).

When a travel vector is found, `u = perpendicularUnit(travel)`. Then apply the centre-ward sign rule: if the dot product of `u` with `(50 - p.x, 50 - p.y)` is negative, negate `u`. A dot product of exactly zero leaves `u` unchanged. This picks the one of the two valid perpendiculars that curls toward the viewBox interior, keeping large nested loops from being clipped at the frame edge. The axis still comes from real travel; only the sign is chosen.

**Radius.** `r_i = baseRadius + boundaryStep + i * nestStep`, for `i` from 0 to `count - 1`, where `baseRadius = LOOP_RADIUS_FRACTION * cellSize`, `nestStep = LOOP_NEST_STEP_FRACTION * cellSize`, and `boundaryStep` is `LOOP_BOUNDARY_STEP_FRACTION * cellSize` when the repeat's cell coincides with the start or end cell and 0 otherwise. Nothing else varies between nested loops — same `p`, same `u`, radius only.

**Boundary coincidence (D-19)** keeps 02-01's cell-equality test: compare the repeat point's `row`/`col` against `points[start]` and `points[end]`, not `atPoint` against the `start`/`end` indices. That correction was made deliberately in 02-01 and remains correct.

**Constants.**

| Constant | Value | Why |
|---|---|---|
| `LOOP_RADIUS_FRACTION` | `0.14` | At stroke-width 2 a loop of radius `0.09 * cellSize` leaves a ~0.9-unit interior on the 4x4 jupiter grid and effectively none on the 9x9 moon grid. At 0.14 the moon case is `r = 1.556`, outer span 3.111, interior ~1.1 units — a visible hole, so it reads as a loop. D-17 leaves exact geometry to Claude's discretion. |
| `LOOP_NEST_STEP_FRACTION` | `0.14` | Circles internally tangent at `p` separate by `2 * step` at the far side. A step of `0.14 * cellSize` gives 3.11 units of far-side separation on the moon grid — 1.1 units of clear gap after stroke-width 2 — so nested loops stay countable at the tightest kamea order. Equivalent to "each extra loop adds one base radius." |
| `LOOP_BOUNDARY_STEP_FRACTION` | `0.04` | One modest radius bump so a loop at the start or end cell reads apart from the boundary marker. Deliberately much smaller than a nest step, so a boundary-bumped single loop can never be mistaken for the outer loop of a nested pair. |
| `SINGLE_NODE_END_OFFSET_FRACTION` | `0.14` | Same value `endMarker` uses today via `LOOP_OFFSET_FRACTION`, so D-27 single-letter output is byte-identical (IN-03). |

**Determinism.** Round `r` once through `roundGeometry` and compute `q` from that ROUNDED `r`, so the emitted chord is exactly twice the emitted radius. Round `q` through `roundGeometry` too. Emit every coordinate through `formatCoord`. No randomness, no time, no locale.
