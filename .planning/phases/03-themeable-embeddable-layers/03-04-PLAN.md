## Planner Note — no default-output bytes change in this plan

03-02 rebased every `.svg` snapshot once, for the always-present grid. 03-03 rebased none. **This plan must rebase none either.** `idPrefix` is absent by default and contributes an empty string to the root element's attribute list, so default output is unchanged. The only committed artifact this plan modifies is `worked-example.working.json` (D-48's `render.idPrefix` key). If any `.svg` snapshot diffs, halt rather than record it.

## Planner Note — the JSON-null decision for `render.idPrefix`

D-48 requires the `render` block to record the resolved `idPrefix`. The obvious implementation records `undefined` when absent — but `JSON.stringify` **drops** undefined-valued keys, so the block would serialize with three keys in the default case and four when a prefix is supplied. That makes the working's shape option-dependent, which contradicts the point of the block: a consumer holding only the working should be able to read the same fields every time.

**Emit JSON `null` for an absent `idPrefix`**, so the `render` block's key set is invariant across every option combination. Type the field as string-or-null in the `SigilWorking` typedef. This is executor-visible discretion, decided here rather than left to be rediscovered mid-implementation.

## Planner Note — `idPrefix` validation includes the empty string

D-47 says a wrong-**typed** known option throws. An empty string is correctly typed but would emit an id attribute with an empty value, which is invalid in HTML and useless for the purpose the option exists to serve. Treat an empty string as invalid and throw `E_INVALID_OPTION` for it, and document it in the README. This is a value check layered onto D-47's type check, within the spirit of "option validation lives in the library" (D-47, ARCHITECTURE.md Anti-Pattern 3) rather than a contradiction of it — but it is a planner extension of the locked decision, flagged here so a reviewer sees it as a decision rather than an accident.
