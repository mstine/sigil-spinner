# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scoping note (read first):** Sigil Spinner has no application UI — no pages, routes, components, forms, or user-facing copy. What this phase actually ships is a piece of generated visual design (the SVG artifact's default look) plus a CSS custom-property theming API (the `--sigil-*` surface). This document treats that token surface as the design system, the SVG element/class taxonomy as the component inventory, and the `var()` fallback values as the default theme. Every template section below is either filled with the honest artifact-level analog or marked `N/A` with a one-line reason — never fabricated app-UI content.

| Property | Value |

**Multi-embed contract (REND-06, not a visual property but part of the "design system" as embeddable artifact):** the SVG is id-free by construction (D-43); the only route to an emitted `id` is a caller-supplied `idPrefix` option on the root `<svg>` (D-44). No visual/theming implication — noted here because it's part of what makes the artifact safely embeddable, which is this phase's actual "UI" deliverable.

### Element / Class Inventory

Paint order per D-39 (SVG paints in document order): grid → glyph → path → nodes → start → end → loops.

| Layer | Element | Class | Cardinality | New this phase? |
|-------|---------|-------|-------------|------------------|
| Root | `<svg>` | `sigil sigil--<planet>` | 1 | Existing; gains optional `id` only when `idPrefix` supplied (D-44) |
| Grid | `<g>` | `sigil-grid` | 1 | **NEW** (D-32) — always emitted, opacity 0 by default |
| Grid | `<path>` | `sigil-grid-lines` | 1 (all lattice lines in one `d`) | **NEW** (D-33) |
| Grid | `<text>` | `sigil-grid-number` | order² (9 Saturn … 81 Moon) | **NEW** (D-34) |
| Glyph | `<text>` | `sigil-glyph` | 0 or 1 (opt-in via `glyph:true`) | **NEW** (D-36, D-37) |
| Path | `<path>` | `sigil-path` | 0 or 1 | Existing — `d` attribute now conditional on the `curve` option (D-30); markup shape unchanged |
| Nodes | `<circle>` | `sigil-node` | one per visited cell | Existing, unchanged |
| Start | `<circle>` | `sigil-start` | 1 | Existing, unchanged |
| End | `<line>` | `sigil-end` | 1 | Existing, unchanged |
| Loops | `<path>` | `sigil-loop` | one per extra visit to a repeated cell | Existing, unchanged |

**Grid group internal structure (Claude's Discretion, resolved):** `sigil-grid-number` elements are **not** nested in their own sub-`<g>` — they sit as flat siblings of `sigil-grid-lines`, all directly inside `<g class="sigil-grid">`. Rationale: there is deliberately only one opacity toggle for the whole grid layer (see Token Table below), so a nested wrapper group would add markup with no independent behavior to justify it. Rejected alternative: a nested `<g class="sigil-grid-numbers">` with its own opacity — rejected because it implies a second visibility axis the token table doesn't offer, and SC2's wording ("made visible by a CSS rule alone") reads as singular.

**Implementation note (not a design decision, flagging so it isn't lost):** `sigil-grid-lines` is an M/L-only path (line segments, no closed shape) and **must** carry an explicit `fill="none"` — SVG defaults an unfilled path to `fill: black`, which would silently paint a solid black grid square over the whole viewBox the moment `--sigil-grid-opacity` is set above 0.

## Spacing Scale

N/A — the 8-point px spacing scale has no analog here; there is no layout, no page, no viewport. Every geometric value in this artifact is a **fraction of `cellSize(order)`** (`cellSize = 100 / order`, fixed `0 0 100 100` viewBox per D-07), rounded once through the existing `roundGeometry`/`GEOMETRY_PRECISION = 3` pipeline (`src/render/svg.js`). See **Geometry Constants** below for the artifact-level analog.

Exceptions: `--sigil-stroke-width` (existing, frozen) and `--sigil-marker-stroke`-driven strokes stay flat absolute literals (default `2`), independent of kamea order — established Phase 1 precedent, unchanged this phase.

**Existing (Phase 1/2, unchanged):**

| Constant | Fraction of `cellSize` | Controls |
|----------|------------------------|----------|
| `NODE_RADIUS_FRACTION` | 0.06 | `sigil-node` radius |
| `START_RADIUS_FRACTION` | 0.1 | `sigil-start` radius |
| `END_BAR_LENGTH_FRACTION` | 0.32 | `sigil-end` bar length |
| `LOOP_RADIUS_FRACTION` | 0.14 | `sigil-loop` base radius |
| `SINGLE_NODE_END_OFFSET_FRACTION` | 0.14 | single-node end-bar offset (D-27) |
| `LOOP_NEST_STEP_FRACTION` | 0.14 | nested-loop radius growth (D-18) |
| `LOOP_BOUNDARY_STEP_FRACTION` | 0.04 | boundary-marker radius bump (D-19) |

**New this phase** (per CONTEXT.md's Claude's Discretion: "consistent with the existing `cellSize`-derived fraction constants pattern, never hardcoded absolute units" — applied to grid stroke-width, grid-number font-size, and glyph size specifically, all baked as the `var()` fallback literal at render time, so the emitted fallback legitimately differs per planet):

| Constant | Fraction of `cellSize` | Controls | Rationale |
|----------|------------------------|----------|-----------|
| `GRID_STROKE_WIDTH_FRACTION` | 0.02 | `--sigil-grid-stroke-width` fallback | Keeps lattice-line thickness visually proportional across all seven orders — a flat literal would read as chunky on Moon's tight 9×9 grid and hairline-thin on Saturn's coarse 3×3 |
| `GRID_NUMBER_FONT_SIZE_FRACTION` | 0.4 | `--sigil-grid-number-font-size` fallback | Verified arithmetically (below) to fit 2-digit numbers (up to 81, Moon) inside their cell at every order with comfortable margin |
| `GLYPH_SIZE_FRACTION` | 0.9 | `--sigil-glyph-size` fallback | Glyph is anchored at the fixed viewBox center regardless of order (D-38), but sizing it "about one cell" keeps it proportionally consistent with the traced path's own visual density — a flat literal would look oversized against Moon's fine 9×9 detail and undersized against Saturn's coarse 3×3 detail |

**Computed defaults by planet** (for executor/checker reference — these are the literal `var()` fallback values that will appear baked into each planet's emitted SVG):

| Planet | order | `cellSize` | `--sigil-grid-stroke-width` fallback | `--sigil-grid-number-font-size` fallback | `--sigil-glyph-size` fallback |
|--------|-------|------------|----------------------------------------|--------------------------------------------|----------------------------------|
| Saturn | 3 | 33.333 | 0.667 | 13.333 | 30 |
| Jupiter | 4 | 25 | 0.5 | 10 | 22.5 |
| Mars | 5 | 20 | 0.4 | 8 | 18 |
| Sun | 6 | 16.667 | 0.333 | 6.667 | 15 |
| Venus | 7 | 14.286 | 0.286 | 5.714 | 12.857 |
| Mercury | 8 | 12.5 | 0.25 | 5 | 11.25 |
| Moon | 9 | 11.111 | 0.222 | 4.444 | 10 |

Fit check (worst case, Moon, 2-digit numbers up to 81): font-size 4.444 × ~1.2 width-per-2-digit-string ≈ 5.3 units of text width inside an 11.111-wide cell — under 50% cell-width occupancy, comfortable margin on all sides.

## Typography

N/A for Body/Label/Heading/Display — there is no prose, no UI text, no document content in this artifact.

Real analog — the two text elements this phase introduces:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | N/A — no application text | — | — |
| Label | N/A | — | — |
| Heading | N/A | — | — |
| Display | N/A | — | — |
| Grid cell number (`sigil-grid-number`) | `--sigil-grid-number-font-size`, default `0.4 × cellSize` per planet (4.444–13.333, see table above) | normal — no `font-weight` token this phase; not part of REND-05's locked scope | N/A — single centered glyph via `text-anchor="middle" dominant-baseline="central"` (D-34), not a block of text with line-height |
| Planetary glyph (`sigil-glyph`) | `--sigil-glyph-size`, default `0.9 × cellSize` per planet (10–30, see table above) | normal | N/A — identical centering idiom (D-38/Pattern 5), anchored at fixed point `(50, 50)` |

**Centering convention:** both new text elements use `text-anchor="middle"` + `dominant-baseline="central"` — the same pair, deliberately, not `dominant-baseline="middle"` (research Pattern 5: `central`'s ideographic-first baseline-table fallback is the more font-agnostic choice for non-alphabetic glyphs, and D-34 already committed to this pair for grid numbers — using anything else for the glyph layer would introduce a second, undocumented centering convention). These two attributes are typographic layout, not themeable presentation, and must not be flagged by the D-42 enforcement guard.

**Font coverage disclosure (required README content, D-38):** glyph rendering depends on the viewer's font stack covering the Miscellaneous Symbols block (U+2600–26FF). No fallback/tofu-avoidance is implemented in code this phase — this is a documented, accepted limitation, not a bug. Two of the seven glyphs (♀ Venus U+2640, ♂ Mars U+2642) additionally carry the Unicode `Emoji` property; every glyph in `src/render/glyphs.js`'s map is suffixed with Variation Selector-15 (U+FE0E) to force text presentation deterministically across all seven, sidestepping platform emoji-fallback inconsistency (research Pitfall C).

## Color

N/A for a literal 60/30/10 hex split — there is no page background, no chrome. Real analog below, expressed through the paint strategy rather than fixed hex values (every default is `currentColor`, deliberately — see rationale).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | N/A — analog: `currentColor` inheritance. `--sigil-stroke`, `--sigil-marker-stroke`, `--sigil-node-fill` all default to `currentColor` (frozen, D-40) — the traced path + markers (the artifact's primary visual weight) always match whatever text color the embedding page already set on the containing element |
| Secondary (30%) | N/A — analog: the grid scaffolding layer. `--sigil-grid-stroke` and `--sigil-grid-number-fill` both default `currentColor`, opacity 0 (hidden). When a site reveals it, it inherits the same color as the primary path with zero extra CSS — never a hardcoded gray |
| Accent (10%) | N/A — analog: the glyph layer. `--sigil-glyph-fill` defaults `currentColor` too, but the glyph is the one element whose *presence* (not just its color) is a deliberate visual statement (D-36's asymmetry: the glyph changes what the sigil *is*; the grid is scaffolding) |
| Destructive | N/A — no destructive actions exist anywhere in this phase (headless generator; no delete/remove/undo operations) |

Accent reserved for: **the `sigil-glyph` text element only.** No other element in this phase's output carries a distinguishing semantic color — every paint property in the entire token surface defaults to `currentColor`, by design, so contrast is inherited from the embedding page rather than asserted by this library. This is also the accessibility answer for light/dark embedding backgrounds: because nothing defaults to a fixed hex, a sigil embedded on a light page and the same sigil embedded on a dark page both automatically meet whatever contrast ratio the site's own text already meets against its own background — the library makes no independent contrast claim and needs none.

**Geometry theming escape hatch (D-41, restated for completeness):** node radius, grid-lattice line positions, and the glyph's `x`/`y` anchor are literal (not `var()`-wrapped) — `var()` silently no-ops inside non-CSS-mapped attributes (research Pitfall B). The README documents the honest alternative: SVG2 exposes `r`, `cx`, `cy`, `x`, `y` as real CSS properties in modern browsers (`rx` confirmed Baseline 2024; siblings assumed to share support, MEDIUM confidence per RESEARCH.md Assumption A2) — a site wanting different geometry sets it directly in CSS rather than this tool faking a hook that wouldn't resolve.

### Backstop

Each of the following lifts into `must_haves.truths` as a flat-scalar `{ statement, verification: backstop }` marker. At verify time, a backstop the verifier cannot confirm with explicit wired evidence abstains to `human_needed` (`insufficient_spec`) rather than passing silently.

| # | Category | Element(s) | statement | verification |
|---|----------|-----------|-----------|--------------|
| B1 | overflow | E3 path | In curve mode, no emitted Bézier control point or curve extremum falls outside the `0 0 100 100` viewBox for any of the seven planets across the determinism-matrix statements. *(A centripetal Catmull-Rom curve can bulge outside the convex hull of its control polyline — a segment hugging the frame edge can therefore render outside the viewBox and clip. No locked decision addresses this; the straight-segment renderer could not produce it because a polyline never leaves its own hull.)* | backstop |
| B2 | error | E3, E4 | With `curve:true`, a statement whose number sequence contains a consecutive repeat (producing coincident points and a zero-length knot interval) emits no `NaN`, no `Infinity`, and no empty coordinate in the `sigil-path` `d` attribute. *(Research Pattern 2 / Pitfall A — the centripetal parameterization's `\|Pi+1 − Pi\|^α` term is zero here; `cellCenter` rounds once before returning, so the guard can test exact `=== 0` rather than an epsilon.)* | backstop |
| B3 | zero-one-many | E4 loops | A repeat run landing on the sigil's start or end cell renders correctly in **curve** mode — boundary-bumped loop radius (D-19) and the start/end markers all present and non-overlapping. *(D-30 asserts marker geometry is independent of curve mode; no existing snapshot combines a boundary repeat with `curve:true`, so this is asserted rather than demonstrated.)* | backstop |
| B4 | populated | all layers | For at least one planet, an all-layers-on render (grid revealed + `glyph:true` + `curve:true`) emits the layers in exactly the D-39 document order: grid, glyph, path, nodes, start, end, loops. *(Paint order is correctness here — SVG paints in document order, so a reordering silently moves the grid in front of the sigil.)* | backstop |
| B5 | partial | E1 grid | Revealing the grid via `--sigil-grid-opacity` alone produces a visible lattice **and** visible cell numbers with no second CSS rule required, and does not paint a filled black square over the viewBox. *(The `sigil-grid-lines` path is M/L-only; SVG defaults an unfilled path to `fill: black`, so the explicit `fill="none"` is load-bearing and only observable once opacity is raised — exactly the state no default-render test exercises.)* | backstop |
