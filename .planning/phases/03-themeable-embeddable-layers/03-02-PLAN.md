<objective>
Deliver REND-03: the kamea grid layer — cell borders and the square's actual numbers — rendered behind the sigil in every output, hidden by default, and revealable with a single CSS declaration.

This is the phase's second vertical slice, riding the option seam 03-01 proved. It adds no flag and no option (D-32) — the grid is unconditional markup whose visibility is a CSS question, which is exactly what Success Criterion 2 asks for. After this plan, a site that writes `.sigil-grid { --sigil-grid-opacity: 0.3 }` sees the magic square the sigil was traced on, for any of the seven planets, with no change to the generated markup.

**Phase goal (verbatim from ROADMAP.md):** "A site can embed several sigils on one page and restyle every one of them entirely from CSS — grid, glyph, and curve options included — without touching the generated markup."

Purpose: the grid is the layer that makes a sigil *legible as a derivation* rather than an opaque glyph — a practitioner can see the square and check the trace by eye. It is also the one layer that changes default output bytes, which is why it is isolated in its own slice with its own snapshot rebase.

Output: `gridLayer` in `src/render/svg.js`, the `kamea` render-option seam in `generate.js`, two new fraction constants, four new class names' worth of markup, six new documented `--sigil-*` properties, and a one-time rebase of every existing SVG file snapshot.

## Planner Note — this plan rebases every SVG file snapshot, exactly once

D-32 makes the grid layer unconditional. Every render for every planet therefore gains a `<g class="sigil-grid">` group, and **every committed `.svg` file snapshot changes in this plan**. That is correct and expected here and nowhere else in Phase 3:

- 03-01 changed zero `.svg` snapshots.
- **03-02 (this plan) rebases all of them, in one reviewed commit.**
- 03-03 and 03-04 must again change zero default-output `.svg` bytes.

D-29's byte-identity guarantee ("existing determinism snapshots must not need rebasing **because a new option exists**") is scoped to options. The grid is not an option — it is mandated markup. Review the rebase diff for shape, not just for green: every rebased snapshot should differ from its predecessor by exactly one inserted `<g class="sigil-grid">…</g>` block at the head of the element list and nothing else.

## Planner Note — no `--grid` flag, deliberately

`.claude/CLAUDE.md` anticipates a `--grid` flag. **D-32 drops it.** Success Criterion 2 requires the grid to be "present in the output, hidden by default, and made visible by a CSS rule alone." A flag would mean *absent* by default, not *hidden* — a materially different contract, and one that would put the grid outside the reach of a site's stylesheet entirely. The divergence from the stack doc is deliberate and is recorded here rather than left silent. Do not add a `grid` entry to `parseArgs`'s options block and do not add a `grid` key to `resolveOptions`'s known-option table.
