## Planner Note — the `--grid` divergence from `.claude/CLAUDE.md`

`.claude/CLAUDE.md` names `--grid` in its anticipated CLI flag surface (`--planet`, `--curve`, `--grid`, `--glyph`, `--out`). **D-32 deliberately drops `--grid`**: Success Criterion 2 requires the grid to be "present in the output, hidden by default, and made visible by a CSS rule alone", which a flag would contradict — a flag means the grid is *absent* by default, not *hidden*. This plan and 03-02 implement no `--grid` flag. The stack doc's flag list is aspirational, not a contract; this divergence is deliberate and recorded here rather than left as a silent contradiction. (Also note `--out` in that doc is spelled `--output` in the shipped CLI; that divergence predates this phase and is not changed here.)

## Planner Note — the D-29 / D-32 byte-identity tension

D-29 guarantees straight-segment output stays "byte-identical to Phase 2 output — the existing determinism snapshots must not need rebasing **because a new option exists**." D-32 mandates that the grid layer is **always emitted**, which by construction changes the bytes of every default render.

These are reconciled at the *option* level, not the document level: **no new option may change default output**, and the grid is not an option. Concretely:

- **This plan (03-01)** changes zero SVG file snapshots — `glyphLayer` returns an empty string when `glyph` is falsy and vanishes through the existing `.filter(Boolean)`. It DOES rebase `test/__file_snapshots__/worked-example.working.json`, because D-48 adds the `render` block (CONTEXT.md rates D-48 `costly` for exactly this reason).
- **03-02** rebases every SVG file snapshot exactly once, in one reviewed commit, when the always-present grid layer lands.
- **03-03 and 03-04** must again change no default-output bytes.

An executor who sees SVG snapshots diff in this plan has a bug, not an expectation.
