<scope_finding>
## Surfaced finding: the fix is larger than one line, and here is the measurement that proves it

The verification report proposed the minimal fix as `if (excerpt.length === 0) continue;` — "a one-line guard plus a regression fixture, entirely contained in the test file." The **boundary holds**: everything below is inside `test/citations.test.js`, and no production code moves. The **one-line characterisation does not hold**, for two measured reasons. Both are reported here rather than absorbed silently.

**1. The empty-string guard alone leaves the same defect one character wider.** `String.prototype.includes` is vacuous for the empty needle, which is what CR-01 names. But it is also near-vacuous for any very short needle. Measured against the real `.planning/milestones/v1.0-research/ARCHITECTURE.md`, an excerpt of `a` is ACCEPTED by the current rule, and is still ACCEPTED by a non-empty-only guard. A rule that treats a single arbitrary character as proof that an author checked a heading verifies nothing — it is CR-01 with one more keystroke. So the rule needs to be discriminating, not merely non-empty.

**A minimum-length floor is the wrong instrument, and this was measured too.** Across the seven documents the tree cites, there are 185 headings; **48 are shorter than 19 characters** (the shortest excerpt any real citation currently uses) and **10 are shorter than 12** — including `CLI`, `Usage`, `Sources`, `Summary`, `Library`, `Metadata`, `Data Flow`, `Determinism`. Any length floor high enough to reject `a` would also reject a legitimate future citation to one of those headings. The discriminating property is not length — it is **whether the excerpt starts where the heading starts**. Requiring the excerpt to be a *prefix* of a real heading rather than any substring rejects `a` and `Boundaries` while accepting `Sources` and all 33 current citations. Verified: 33/33 real path-token citations satisfy the prefix rule; zero citation-site repair is required.

**2. WR-01 cannot be fixed by any excerpt-content guard.** It is a pairing defect: which excerpt is allowed to back which token. It is in scope per the gap contract, and it needs the candidate-selection logic changed. Measured evidence that it is real, not theoretical: **every one of the 33 real citations has its backing excerpt 4 or 5 characters from its path token** (the canonical `"<excerpt>" in <path>` form), yet the checker searches ±200 characters and accepts the *first* quote that happens to resolve. A synthetic token with no adjacent excerpt, sitting 150 characters from a neighbour's valid excerpt for the same document, is ACCEPTED today. The dense multi-citation blocks WR-01 names are already in the tree — `src/path/buildPath.js:51-53` chains two citations to two different documents inside one parenthetical, and it resolves correctly today only because the two excerpts happen not to cross-resolve, not by construction.

**3. A seam is required to test any of this.** Every function in `test/citations.test.js` is module-private and `checkFile` reads its own file from disk, so there is currently no way to feed a synthetic defect shape through the real rule path. Splitting `checkFile` into a pure `checkSource(source, relPath)` plus a thin file-reading wrapper is the minimum change that makes a regression fixture possible without a second file. This is a seam, not a rewrite.

**Load-bearing hazard for Task 2.** 05-01's own deviation log records that a literal `style=""` in a comment corrupted quote pairing, because `QUOTE_RE` pairing is positional — the second quote of one construct became the opening quote of the next. Confirmed while measuring this plan: scanning candidate quotes across the whole comment blob instead of within the existing citation window makes `src/generate.js:142` stop resolving, purely from re-anchored pairing. **The scan span must stay exactly the existing `citationWindow`.** The adjacency bound is a filter applied to candidates found within that span, never a replacement for it.
</scope_finding>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| citation author → committed drift guard | An author writes a citation and the guard is the only thing asserting it constitutes real evidence. If the guard accepts non-evidence, the boundary is open and nothing downstream re-checks it. |
| future contributor → source comments | A contributor reads a citation and trusts the target document to justify the discipline the comment describes. A guard that green-lights an unbacked citation launders that trust. |
| `.planning/` research documents → shipped source | Research documents are replaced in place at the same path each milestone, so every citation is time-bound by construction and the guard is the only recurring check. |
