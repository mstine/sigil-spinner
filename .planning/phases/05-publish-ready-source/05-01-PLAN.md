The checker walks every `.js` file under `src/` and `bin/`. For each file it extracts **comment text only** — strip leading `*`, `//` and `/*` prefixes, join lines, and collapse runs of whitespace to single spaces, so a citation wrapped across several JSDoc lines is still one contiguous string. Note that `test/render/svg.test.js` already establishes this comment-stripping technique in this repo; follow it rather than inventing a parser.

It then enforces two rules and one floor:

**R1 — every path token resolves.** For every token matching a markdown filename in the normalized comment text: the token must be fully qualified (begin with `.planning/`, or be exactly `README.md`); the path must exist on disk relative to the repo root; and within the same citation window there must be a double-quoted excerpt whose whitespace-collapsed text appears as a substring of some markdown heading line (a line beginning with one or more `#`) in that target file. Define the citation window as the enclosing parenthetical if the path sits inside one, otherwise a bounded span of the normalized text around the token — 200 characters either side is sufficient for every site in this repo.

**R2 — every bare label is backed in its own file.** For every label token of the form `Pitfall <N-or-single-letter>`, `Pattern <N>`, or `Anti-Pattern <N>` in the normalized comment text: the same file must contain at least one R1-valid citation whose quoted excerpt *begins with that exact label string*. This is deliberately file-scoped, not window-scoped, so a file cites a document in full once per label and may then refer to the label freely — which is why sites 21, 33 and 34 need no path of their own.

**Site-count floor.** Assert the total number of citation sites found across `src/` and `bin/` is at least 34. This is the anti-appeasement guard: the cheapest way to satisfy R1 and R2 is to delete citations, and this floor makes that fail. Record `34` in a named constant with a comment stating it is the plan-time enumerated count and that a *deliberate* future addition should raise it, never lower it.

Findings must be collected across all files and reported together, sorted by file path then line number, so a failure message is stable across repeat runs and names every offender in one pass rather than one per run. A file with zero citations contributes zero findings and is not an error.
