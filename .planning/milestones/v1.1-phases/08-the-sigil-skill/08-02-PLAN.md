Open with a header comment carrying the guard's identity and its constraints, per D-107: this is SKILL-03's drift guard; `bin/sigil-spinner.js` is read as TEXT and never imported, because it reads `process.argv` at module load and its `parseArgs` failure branch calls `diagnose()`, which writes to stderr and calls `process.exit` — the same class of import-time side effect that forced `test/element-docs.test.js` to text-parse the element source, and the same methodology `test/citations.test.js` already applies to JavaScript sources; and the flag list is never restated as a literal on either side, continuing the guards-are-keyed-not-transcribed precedent this repo has now followed four times.

Write `parseCliOptionKeys(source)` taking source text and returning a set of key names. Locate the options anchor, then extract the block by counting braces from the character after the opening brace until depth returns to zero — do not use a per-line regex. The reason matters and belongs in a comment: the element template's subject is a flat array literal with one bracket pair, whereas this subject is a nested multi-line object where every entry is itself a brace-delimited value. A regex assuming one key per line matches all seven today and would silently drop matches after a formatter collapses two short entries onto one line or after someone adds an option whose default spans lines — an undercount with no error, which is the failure mode the zero-match guard exists to catch but which a partial undercount slips past. Split the block's interior at depth-zero commas and take each entry's leading key, accepting both a bare identifier and a single-quoted one, since one of the current keys is hyphenated and therefore quoted. Throw an Error naming the missing anchor and the file if the anchor is not found.

Write `parseSkillFlagTokens(md)` taking markdown text and returning a set of token names with the leading double hyphen stripped. Anchor the regex to the table-row shape — line start, pipe, whitespace, a backticked double-hyphen token, whitespace, pipe — so that a flag mentioned in ordinary prose elsewhere in the skill body is not counted as documented. This anchoring is load-bearing for plan 08-03, which adds prose sections that name flags. Throw a named Error if zero rows match.

Declare `INTENTIONALLY_UNDOCUMENTED` per D-108 as a module-level array, empty, with a comment stating three things: it is empty as a fact about the current state rather than as a design absence; every future entry requires a written reason beside it; and its purpose is to make omitting a flag a deliberate edit with a justification instead of letting the check quietly degrade into one direction the first time someone finds the reverse direction inconvenient. Subtract its members from the CLI-side set before diffing. This mirrors the shape of the resolve-only discriminator the pack-install test already uses.

First test, the zero-match guard: assert both parsed sets are non-empty, each with an assertion message naming which side parsed nothing. This is the guard that stops a regex which has silently stopped matching from turning the whole check green, and it is copied directly from the template.

Second test, the bidirectional assertion: compute the skill-only and CLI-only differences, assert each equals the empty array, and put the offending token list into each assertion's message — one message for a flag the skill documents that the CLI lacks, one for a CLI option the skill omits.

Third, a separate soundness describe block satisfying D-109's fail-first requirement, constructing every fixture as a literal source string rather than a file on disk — which is exactly why both parse functions take text. It contains at minimum: a proof that a fabricated skill table row for a nonexistent flag produces a non-empty skill-only difference against the real CLI keys; a proof that a fabricated CLI source string carrying an extra option key produces a non-empty CLI-only difference against the real skill tokens; a proof that the brace-counted extraction is insensitive to formatting, by running it against a fixture whose options literal places two entries on one line and asserting the same key set; a proof that a double-hyphen token appearing in prose rather than in a table row is not counted; and a proof that a token placed in the allowlist is genuinely subtracted, so the empty array is demonstrated to have machinery behind it rather than being assumed inert-but-wired.

Create `test/skill-install-parity.test.js` using only Node builtins.

Resolve two roots at module level: the repository's skill source directory relative to `REPO_ROOT`, and the installed destination built from `os.homedir()` joined with the same fixed segments `scripts/skill-install.js` uses. Both must be constructed the same way as the install script so a change in one is visible against the other.

Write the conditional no-op per D-101 as this repo's single stated exception to its own fail-loud-never-skip convention. Everywhere else in this suite a missing prerequisite fails with instructions — the browser tests error with an install command rather than skipping when the engine is absent. The two cases are genuinely different and the comment must say so: a missing browser engine is a prerequisite the developer should fix, whereas an absent personal skill directory is the correct state on every machine that is not the author's, and conflating the two would train the suite's red to mean nothing. The message is not optional: an unexplained pass is exactly what this exception decays into without it.

When the destination does exist, walk the repository's skill tree recursively, and for each file compare its bytes with the corresponding file under the destination. Collect three kinds of finding rather than throwing at the first: a destination file that is missing, a destination file whose contents differ, and a destination file with no repository counterpart. Sort the collected paths stably and fail once with all of them in a single message, following the collect-then-report-once discipline the citation guard already uses — a stable sort also means repeat runs produce identical output.

Add a second, unconditional test asserting the repository's skill tree contains at least one file. Without it, an empty or mis-resolved source root would make every comparison vacuously true on a machine where the destination exists — the same class of vacuous-pass defect this project's citation checker shipped once and had to repair.

Do not add any vitest skip API. The no-op is a plain early return with a printed reason, so the test reports as a genuine pass with a visible explanation rather than as a skip the reporter can collapse.
