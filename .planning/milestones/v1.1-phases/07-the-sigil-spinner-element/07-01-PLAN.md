Wire ONE path through every layer this phase touches: attribute read, option assembly, `generateSigil` call, light-DOM injection, rendered geometry in Chromium. No other call sites, no batching, real error handling on the single path.

**Module contract.** Exactly one import statement: `generateSigil` and `SigilError` from `'../index.js'`, the package's public surface — never a deeper relative path such as `../generate.js` or `../render/svg.js`, which resolves fine in-repo and throws `ERR_PACKAGE_PATH_NOT_EXPORTED` for any external consumer (D-85). No `node:` import in this file, ever. Declare a module-level constant `TAG_NAME` whose value is the string `sigil-spinner`. Define and export a class named `SigilSpinnerElement` extending `HTMLElement`, and keep the module's registration side effect at module scope.

**Attribute surface (D-79, D-80, D-87).** `static get observedAttributes()` returns exactly, in this order: `statement`, `planet`, `curve`, `glyph`, `id-prefix`, and the title-toggle name locked at the first checkpoint. These are the CLI's long-flag names with the leading dashes dropped and kebab-case preserved; the title toggle is the single deliberate exception, because `title` is a global HTML attribute that renders a browser tooltip and collides with `options.title`'s unrelated meaning. `--json` and `--output` have no element analog and must not appear.

**Render path.** One private render method, called unconditionally from `connectedCallback()` and from `attributeChangedCallback()` only when `this.isConnected` is true (D-88). Read `statement` and `planet` with `getAttribute` and pass both through verbatim — no trimming, no case folding, no Unicode normalization of the element's own. All letter handling belongs to the library.

**Inert state (D-91).** When either `statement` or `planet` returns `null` (the attribute is genuinely absent), clear the element to zero element children by assigning the empty string to `innerHTML`, remove `data-sigil-error` if present, throw nothing, log nothing, and return. This must hold both for a never-rendered element and for one that rendered and then had a required attribute removed. An attribute that is PRESENT BUT EMPTY is not absent: pass the empty string straight to `generateSigil` and let the library's own `E_MISSING_STATEMENT` surface through the error path below. Never coerce empty to absent, never coerce absent to empty.

**Boolean options (D-81).** `curve`, `glyph`, and the title toggle are true when `this.hasAttribute(...)` is true, regardless of the attribute's value — the same presence semantics the platform uses for `disabled` and `hidden`. The consequence is real and stays undisguised: `curve="false"` enables curves; removing the attribute is the only way to disable it. Plan 07-02 pins this in a browser test and plan 07-03 documents it.

**Option assembly.** Build the options object with the library's camelCase keys — `curve`, `glyph`, `idPrefix` from the `id-prefix` attribute, and `title` from the presence of the title toggle. The mapping happens only at this call boundary; the library's camelCase names are never exposed as attributes. Pass through whatever `getAttribute('id-prefix')` returned, including `null`, and let `generateSigil` own validation — the element validates nothing itself, the same posture `bin/sigil-spinner.js` already takes.

**Error handling (D-92).** Wrap the `generateSigil` call in ONE synchronous try/catch that performs all DOM writes in a single pass rather than in two separate mutation passes. On success: assign the whole, unmodified `svg` string to `innerHTML`, then remove `data-sigil-error`. On a caught `SigilError`: assign the empty string to `innerHTML`, call `console.error` with the literal first argument text `<sigil-spinner> failed to render:` and the full unmodified error object as the second argument (its `message`, `code`, and `details` stay intact — no re-wrapping, no re-summarizing), then set `data-sigil-error` to the error's `code`. Re-throw anything that is not a `SigilError`. Never render a placeholder graphic — the element has no visual vocabulary of its own. `data-sigil-error` is deliberately absent from `observedAttributes`, so writing it from inside the callback cannot re-enter `attributeChangedCallback`.

**The injection rule (D-86).** Assign either the entire unmodified `generateSigil` output or an empty string to `innerHTML` — never a template literal, never string concatenation, never a hand-built wrapper element around the library's output. Attribute values are attacker-reachable and the library's `escapeXml` protects only what passes through `generateSigil`; a locally-built markup string would be a second injection surface that escaping never touches. If the element ever needs to add content of its own, it goes through `document.createElement` plus `textContent`.

**Light DOM (D-82).** Per the second checkpoint's outcome, the SVG is written directly into the element's own children so page CSS reaches it through both the 15 `--sigil-*` custom properties and the seven semantic classes, identically to a hand-pasted `<svg>`. The element never calls the shadow-root attachment API.

**Synchronicity (D-89).** The render is a synchronous whole-content replacement — no diffing, no batching, no coalescing, and no asynchronous primitive of any kind: no promise awaiting, no timer scheduling, no microtask queueing, no animation-frame scheduling, no mutation observation. Three attribute writes render three times; that is the accepted cost.

**No synthesis (D-93).** The element derives nothing — no generated `id-prefix`, no hash of the inputs, no instance counter. WRAP-03's no-collision claim holds by construction because the default artifact emits zero `id` attributes; generating uniqueness here would make the element's output differ from the raw-SVG path for identical inputs.

**Guarded registration (D-90).** At module scope, call `customElements.get(TAG_NAME)` first and only call `customElements.define(TAG_NAME, SigilSpinnerElement)` when it returns a falsy value. `customElements.define` throws `NotSupportedError` on a duplicate tag name or duplicate constructor and the platform ships no unregister or redefine API, so an unguarded double load is unrecoverable within the page.

**Comments and citations.** Cite decisions as bare `D-NN` identifiers in comments. If any comment names a markdown file it must be a fully qualified path beginning with `.planning/` plus a double-quoted excerpt that is a substring of a real heading in that file, and any bare `Pitfall N` / `Pattern N` / `Anti-Pattern N` label needs a fully qualified backing citation in the same file — `test/citations.test.js` enforces both mechanically. Fail loudly, never skip.
