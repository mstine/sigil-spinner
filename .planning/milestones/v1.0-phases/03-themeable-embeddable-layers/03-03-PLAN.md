## Planner Note — a SIGN ERROR in 03-RESEARCH.md's curve code example

`03-RESEARCH.md`'s "Full curved-segment builder" code example computes the second tangent as `tangent(Q3, Q2, Q1, t23, t12)` — reusing the helper with its arguments in reversed roles — and then emits `B2 = Q2 - m2/3`. **Those two lines are inconsistent with each other and the example is wrong.**

The role-swapped call returns the NEGATION of the tangent the formula defines. Substituting into the helper's own body: `tangent(A,B,C,tAB,tBC)` returns `(C - B) + tBC * ((B - A)/tAB - (C - A)/(tAB + tBC))`, so `tangent(Q3, Q2, Q1, t23, t12)` expands to `-[(Q2 - Q1) + t12 * ((Q3 - Q2)/t23 - (Q3 - Q1)/(t12 + t23))]`, which is exactly minus the m2 the research text states one section earlier. Feeding that negated value into `B2 = Q2 - m2/3` yields `Q2 + m2/3` — the control point placed on the far side of the endpoint, so every curve overshoots its own endpoint.

The research TEXT (Pattern 3) is correct; only its illustrative code is wrong. **Implement the formulas as written in Pattern 3, with both tangents computed by explicit non-swapped expressions.** Task 1 carries a numeric acceptance criterion that catches this sign specifically — the correct implementation places the second control point of a collinear triple at x 16.667, the sign-error implementation places it at x 23.333, outside the segment entirely.

## Planner Note — `roundGeometry` moves to `coords.js` to avoid an import cycle

03-CONTEXT.md leaves it to discretion whether `curve.js` imports `roundGeometry` from `svg.js` or the function is hoisted. **Hoist it into `src/render/coords.js`.** The reason is structural, not aesthetic: `svg.js` must import `curvedPathD` from `curve.js`, so having `curve.js` import `roundGeometry` back from `svg.js` creates a module cycle. ESM tolerates cycles but they are fragile under partial initialization and they contradict `coords.js`'s own header, which already declares itself the module every other module goes through for shared geometry.

Move `GEOMETRY_PRECISION` and `roundGeometry` into `coords.js` as an exported pair, delete the duplicates from `svg.js`, and import them there. Keep `coords.js`'s existing private `round` and `COORDINATE_PRECISION` as they are: they govern cell centers, `GEOMETRY_PRECISION` governs derived marker and curve geometry, and the two are deliberately separate constants that currently share the value 3 — the same separate-constants-for-separate-contracts discipline the `SINGLE_NODE_END_OFFSET_FRACTION` split established (review finding IN-03). Document that in the moved constant's comment. This move must change zero output bytes.
