## Tech Debt — 11 items across 3 phases

Every item below was re-confirmed against the live codebase during this audit, not transcribed from the phase reviews.

### Phase 1 — First Sigil, End to End

**WR-03 · Validation ordering masks a second error** *(Warning)*
`generateSigil('AEIOU','pluto')` throws `E_EMPTY_SEQUENCE`, not `E_UNKNOWN_PLANET` — statement-content validation runs before planet-identity validation in `src/generate.js:68-79`. Each path is independently tested; the combined case reports only the first failure. Confirmed live 2026-08-07.

**WR-04 · Raw TypeError on a hypothetical partial kamea set** *(Warning, latent)*
`gridSize`/`kameaGrid` in `src/data/kamea.js:209-226` would throw a raw `TypeError` rather than a `SigilError` if a kamea set missing one of the seven planets were ever registered. Unreachable today — `agrippa` is the only set and it is complete.

**WR-02 · Error codes not re-exported** *(Info)*
`src/index.js` exports only `SigilError` and `generateSigil`. The `E_*` code constants stay private, so `bin/sigil-spinner.js` hardcodes them as object keys with no drift protection if one is renamed. Confirmed live 2026-08-07.

### Phase 2 — Every Planet, Every Statement

**WR-01 · `E_CLI_STDIN` has no deterministic test** *(Warning, disclosed)*
The handler exists and is correctly scoped (`bin/sigil-spinner.js:117-121`), but its `EAGAIN`-on-TTY trigger is not reproducible in a non-TTY subprocess harness. Disclosed by both the code review and 02-04-SUMMARY.md — a known coverage hole, not a silent one.

**WR-02 · Misleading doc comment** *(Warning)*
`perpendicularUnit`'s zero-length fallback in `src/render/svg.js` is annotated "unreachable" and isn't. Pre-existing, documentation-accuracy only.

**WR-03 · README omits two working fields** *(Warning)*
The README's `working` field list documents neither `keptTrail` nor `repeats` — `grep -c keptTrail README.md` returns 0. Both are real, shipped fields consumers will encounter. Confirmed live 2026-08-07.

**WR-04 · CLI silently discards extra positional arguments** *(Warning)*
`sigil-spinner.js 'I WILL SUCCEED' 'EXTRA ARG' --planet saturn` renders the first statement and says nothing about the second. Confirmed live 2026-08-07. Worth a diagnostic given the tool's otherwise strict argv posture.

### Phase 3 — Themeable, Embeddable Layers

**WR-01 · `working.render` round-trip is broken** *(Warning — the one to fix first)*
`src/render/json.js`'s own doc comment says the `render` block lets "a consumer holding only the working reproduce the exact SVG." It doesn't. `working.render.idPrefix` serializes as JSON `null` when absent, but `resolveOptions` treats only strictly-`undefined` as absent — so the natural round-trip throws:

```
generateSigil('I WILL SUCCEED','saturn').working.render
  → {"curve":false,"glyph":false,"idPrefix":null,"title":false}
generateSigil('I WILL SUCCEED','saturn', <that object>)
  → E_INVALID_OPTION: option "idPrefix" must be a string, got: null
```

This fires in the default, most common case. It affects no roadmap success criterion (none exercise the round-trip), which is why it was correctly held as Warning rather than escalated — but it is a documented contract the code does not honor, and the fix is small. Confirmed live 2026-08-07.

**WR-02 · `-0` serialization unguarded** *(Info, latent)*
`formatCoord`/`roundGeometry` have no `-0` guard. Zero occurrences across all 14 curve-mode snapshots; not exercised by any current input across seven planets and both curve modes.

**IN-01 · Decision ID collision** *(Info, cosmetic)*
`D-12` is cited for two unrelated topics in source comments.

### Cross-cutting

**Phase 2 SUMMARY frontmatter omits `requirements-completed`** *(metadata)*
All four files. Costs the audit its third cross-reference source for six requirements (resolved manually above). Worth backfilling so future audits and any tooling reading that field don't degrade silently.

**`title` option is library-only** *(scope note, not a defect)*
`options.title` works programmatically; there is no `--title` CLI flag. Deliberate, recorded in the Phase 3 summaries.

**No UI-REVIEW.md for Phase 3** *(coverage note)*
Phase 3 carries a UI-SPEC.md and `UI hint: yes`, but the `verify:post` `ui-review` hook is gated on `workflow.ui_review`, which is absent from `.planning/config.json` — so it never fired. The visual claims were covered by hand instead: UAT test 1 (multi-embed CSS restyling, which surfaced and closed G-03-1), test 2 (curve smoothness across seven planets), test 3 (boundary-repeat marker legibility). Coverage exists; it just came from UAT rather than the automated pillar audit.
